# onescript-openapi-generator

Плагин [OpenAPI Generator](https://openapi-generator.tech), который генерирует
клиент [OneScript](https://oscript.io) из спецификации OpenAPI 3.

Плагин реализован как обычный генератор OpenAPI Generator: класс наследует
`DefaultCodegen`, регистрируется через `META-INF/services` и подключается рядом
с `openapi-generator-cli.jar`. Java объединяет описания служб с classpath,
поэтому `-g onescript` работает так же, как встроенные генераторы, — со всем
разбором спецификации, разрешением `$ref` и именованием встроенных схем.

## Что получается на выходе

Готовый к сборке пакет `opm`:

```
packagedef                    описание пакета (все классы перечислены)
lib.config                    реестр классов библиотеки
README.md
src/Классы/
  Конфигурация.os             адрес сервиса, токен, таймаут, заголовки
  СекретнаяСтрока.os          обёртка, не раскрывающая значение при выводе
  ТранспортHTTP.os            сборка запроса, отправка, разбор ответа
  ОтветAPI.os                 код состояния, заголовки, тело, разобранный JSON
  <Тег>Api.os                 по одному классу на тег спецификации
src/Модели/
  <Схема>.os                  по одному классу на схему
```

Зависимости сгенерированного клиента объявлены в `packagedef`, так что `opm`
подтянет их сам:

- [1connector](https://github.com/vbondarevsky/1connector) — транспорт: сборка и
  кодирование строки запроса, разбор ответа, повторы, прокси и SSL.
- [jason](https://github.com/nixel2007/jason) — сериализация и разбор моделей по
  аннотациям.
- [validate](https://github.com/nixel2007/validate) — проверка моделей по
  аннотациям-ограничениям.

## Сборка

Нужен только Docker:

```bash
scripts/build.sh
```

Собирается `target/onescript-openapi-generator-<версия>.jar`.

## Использование

```bash
scripts/generate.sh спецификация.yaml ./out packageName=my-client packageVersion=1.0.0
```

Либо напрямую, рядом с официальным CLI:

```bash
java -cp "onescript-openapi-generator.jar:openapi-generator-cli.jar" \
  org.openapitools.codegen.OpenAPIGenerator generate \
  -g onescript -i спецификация.yaml -o ./out
```

### Параметры

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `packageName` | `openapi-client` | имя пакета opm |
| `packageVersion` | `0.1.0` | версия пакета |
| `packageDescription` | — | описание в `packagedef` |
| `packageAuthor` | — | автор пакета |
| `packageAuthorEmail` | — | адрес автора |
| `environmentVersion` | `2.0.0` | минимальная версия OneScript (её требует jason) |
| `userAgent` | `onescript-openapi-generator` | значение заголовка `User-Agent` |
| `connectorVersion` | `2.3.3` | минимальная версия 1connector в `packagedef` |
| `jasonVersion` | `0.6.0` | минимальная версия jason |
| `validateVersion` | `0.4.0` | минимальная версия validate |

## Проверка результата

`oscript -check` компилирует модуль без запуска — это единственный компиляционный
барьер, который даёт OneScript:

```bash
OSCRIPT=/путь/к/oscript scripts/install-deps.sh   # нужен для проверки
OSCRIPT=/путь/к/oscript scripts/check.sh ./out
```

`install-deps.sh` обязателен: `ТранспортHTTP.os` и каждая модель начинаются с
`#Использовать`, поэтому библиотеки должны резолвиться даже для `oscript -check`,
а не только при запуске.

## Как решения связаны с особенностями OneScript

Несколько неочевидных мест, на которые опирается генератор.

**Разбор URL, кодирование и JSON отданы 1connector.** Встроенного
`HTTPСоединение` для клиента мало: у него нет ни сборки строки запроса, ни
повторов, ни единого способа задать прокси и SSL, а HTTPS включается только
схемой в имени сервера (типа `ЗащищенноеСоединениеOpenSSL` в OneScript нет).
`КоннекторHTTP.ВызватьМетод` закрывает всё это одним вызовом, поэтому транспорт
занимается только тем, что специфично для сгенерированного клиента: заголовками,
токеном, телом и разбором ответа.

**Сегменты пути экранируются вручную.** Параметры строки запроса кодирует
1connector, но сегменты пути подставляются в URL до его разбора, поэтому
`ЭкранироватьСегмент` остаётся на стороне транспорта.

**Исключение несёт текст, а не объект.** `ВызватьИсключение Объект` в OneScript
не сохраняет объект для перехватчика: `ОписаниеОшибки()` вернёт только имя
класса. Отдельный класс исключения был бы бесполезен — его нельзя поймать по
типу. Поэтому при ошибке выбрасывается подробный текст, а для разбора ответа по
полям предусмотрен флаг `ВыбрасыватьИсключениеПриОшибке = Ложь`.

**`Строка(Объект)` возвращает имя класса.** На этом построена `СекретнаяСтрока`:
значение лежит в неэкспортируемой переменной, поэтому `Сообщить(Токен)` выводит
`СекретнаяСтрока`, а не сам токен. Получить значение можно только явно —
`Раскрыть()`.

**Идентификаторы регистронезависимы и могут быть кириллическими.** Два свойства
схемы, различающиеся только регистром, в BSL столкнулись бы, поэтому имена
свойств моделей разводятся при генерации. Кириллица в именах сохраняется:
`DefaultCodegen.sanitizeTag()` вырезает не-ASCII, из-за чего все русские теги
схлопнулись бы в одно (часто пустое) имя и несвязанные операции попали бы в один
класс — метод переопределён.

**`Выполнить` — встроенная функция BSL** (`Execute`), поэтому метод транспорта
называется `ВыполнитьЗапрос`. Список зарезервированных слов включает и русские,
и английские написания: BSL принимает оба.

**Библиотека регистрируется через `lib.config`, а не по соглашению о каталогах.**
Это надёжнее: в поставке OneScript 2.2.0 для macOS arm64 загрузка по соглашению
ломается на вложенном каталоге пакета `asserts`, что каскадом выводит из строя
`cli`, `logos` и `opm`.

**`Соответствие` сохраняет порядок вставки** (в отличие от платформы 1С, где
обход идёт по возрастанию ключа), поэтому порядок полей спецификации доходит до
результата без изменений. Манифесты при этом сортируются намеренно — так
повторная генерация даёт побайтово тот же файл.

## Ограничения

- Тела запросов сериализуются в JSON. `multipart/form-data` генератор не
  использует, хотя 1connector это умеет — при необходимости передайте
  `ДополнительныеПараметры.Файлы` через собственный вызов `КоннекторHTTP`.
- `oneOf` и `anyOf` разворачиваются в свободную коллекцию, а не в отдельный тип.
- Значения типа `Дата` в теле запроса нужно приводить к строке самостоятельно.
- Значения заголовков должны состоять из символов ASCII — это ограничение
  HTTP-стека .NET, на котором работает OneScript. Кириллица в параметрах строки
  запроса, сегментах пути и теле запроса работает: они кодируются отдельно.
- Проверено на OpenAPI 3.0. OpenAPI 2.0 (Swagger) не проверялся.
